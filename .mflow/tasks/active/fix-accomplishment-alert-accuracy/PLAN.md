## Approach

Two independent defects in the `alerts/` package. (1) `OneTimeRewardListener` infers "first fire cape / infernal cape / Dizana's quiver" from loosely matched completion chat text plus a plugin-side "already sent" flag, so it fires for veterans who already own the item. Replace it with the game's own Collection Log new-item message (`New item added to your collection log: <item>`, wording verified against RuneLite's `ScreenshotPlugin.COLLECTION_LOG_TEXT`), so "first time" is decided by the game. (2) `LootAlertListener.TRACKED_ACCOMPLISHMENT_ITEM_IDS` only lists the charged `TUMEKENS_SHADOW` / `SCYTHE_OF_VITUR` IDs, but ToA/ToB drop the uncharged items, so the drops pass the loot-value check but never the accomplishment check; add the uncharged IDs.

## Layers affected

- Alerts (`src/main/java/com/catastrophic/events/alerts/`) — `OneTimeRewardListener.java`, `LootAlertListener.java`
- Tests (`src/test/java/com/catastrophic/events/alerts/`) — new `OneTimeRewardListenerTest.java`

## Conventions to follow

- Allman braces, tab indentation, no `var`, explicit types
- `@Slf4j` + `log.debug(...)` on alert failures
- Keep the `ChatMessageType.GAMEMESSAGE` filter (anti-spoofing, added in consolidate-loot-listeners)
- Constructor `@Inject`; no new dependencies (JUnit 4.12 is already a test dependency)

## Concerns to watch

- WRN-007: `OneTimeRewardListener`'s chat wording was unconfirmed. This task replaces it with wording verified from RuneLite's own source; resolve WRN-007 at ship.
- WRN-008: `net.runelite.api.ItemID` is deprecated. Not migrating here; the two new constants come from the same class for consistency.
- TD-001: no automated tests exist. This task adds the first small JUnit test (pure string matching, no RuneLite runtime needed).
- Known limitation (document, do not fix): the collection-log chat message only appears if the player has the in-game "Collection log - new addition notification" setting enabled; players with it off will post nothing.

## Steps

### Step 1 — Add uncharged Scythe and Shadow IDs
In `src/main/java/com/catastrophic/events/alerts/LootAlertListener.java`, extend `TRACKED_ACCOMPLISHMENT_ITEM_IDS` to: `TWISTED_BOW`, `SCYTHE_OF_VITUR`, `SCYTHE_OF_VITUR_UNCHARGED`, `TUMEKENS_SHADOW`, `TUMEKENS_SHADOW_UNCHARGED`, `ANCIENT_BLOOD_ORNAMENT_KIT`, `PURIFYING_SIGIL`. Charged IDs stay (e.g. PK loot). IDs verified present in the pinned runelite-api (22486, 27277).

### Step 2 — Rewrite OneTimeRewardListener around the collection log message
In `src/main/java/com/catastrophic/events/alerts/OneTimeRewardListener.java`:
- Remove `FIRE_CAPE_TOPIC` / `INFERNAL_CAPE_TOPIC` / `DIZANAS_QUIVER_TOPIC` / `COMPLETION_VERB`, the `fireOnce` flag logic, the `ConfigManager` dependency and `CONFIG_GROUP`.
- Add `COLLECTION_LOG_ENTRY = Pattern.compile("New item added to your collection log: (?<item>[^<]+)")`.
- Add a nested `Reward` enum (FIRE_CAPE, INFERNAL_CAPE, DIZANAS_QUIVER) each holding an item-name pattern, the alert title and summary (titles/summaries unchanged: "Fire Cape" / "achieved their first Fire cape", etc.), plus a package-private `static Reward match(String message)` returning the matching reward or `null`.
- `onChatMessage`: keep the `accomplishmentSharingEnabled()` and `GAMEMESSAGE` gates, call `match(...)`, then post text-only via `alertsApiClient.sendAlert(token, AlertKind.ACCOMPLISHMENT, summary, title, callback)`.
- Update the class javadoc to describe collection-log gating and the in-game setting dependency.

### Step 3 — Add a unit test for the matcher
Create `src/test/java/com/catastrophic/events/alerts/OneTimeRewardListenerTest.java` (JUnit 4): matches `New item added to your collection log: Fire cape` / `Infernal cape` / `Dizana's quiver (uncharged)`; returns null for the old false-positive style text (e.g. "Congratulations, you've completed the Inferno"), for other collection log items, and for near-misses (`Fire cape` embedded in other text, other capes).

### Step 4 — Compile and test
Run `./gradlew compileJava test --console=plain`; both must pass.

### Step 5 — Log decisions
Record via worklog: (a) one-time flags removed and why; (b) uncharged-ID root cause for Shadow plus Scythe fixed alongside; (c) in-game notification setting dependency; (d) first automated test added.
