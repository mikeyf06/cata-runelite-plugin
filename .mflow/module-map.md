## Plugin Core

**Responsibility:** Guice-injected plugin lifecycle (startUp/shutDown), the 45s poll loop, reminder-milestone logic, and the user-facing config schema - the orchestrator that wires the API client's results into the panel's state.
**Entry point:** `CatastrophicEventsPlugin.java`

### Key files
| File | Purpose |
|------|---------|
| `CatastrophicEventsPlugin.java` | Plugin entrypoint: startUp/shutDown, poll loop scheduling (scheduleWithFixedDelay), join-button handler, reminder milestone dedupe (`remindersShown` set), registers/unregisters six EventBus alerts listeners (loot - which also covers the mega-rare accomplishment allowlist, death, coffer, skill milestone, pet drop, one-time reward). `pollEvents()` also calls `questMilestoneListener.checkQuests()` directly each cycle - that listener has no EventBus subscription (see Alerts module). |
| `CatastrophicEventsConfig.java` | RuneLite ConfigGroup interface declaring `token`, `lootSharingEnabled`, `deathScreenshotsEnabled` (both default off/opt-in), `deathMessage` (custom text, default blank), `eventRemindersEnabled` (default off/opt-in, gates the milestone reminders and signed-up-events summary), and `accomplishmentSharingEnabled` / `petDropSharingEnabled` (both default off/opt-in) settings. |

## API Client

**Path:** `src/main/java/com/catastrophic/events/api`
**Responsibility:** Wraps OkHttp calls to the catabot backend's plugin API (`GET /events`, `POST /signup`, `POST /alerts`) behind an async callback interface, and classifies failures so callers can branch on cause (unauthorized vs. network vs. server).
**Entry point:** `EventsApiClient.java`

### Key files
| File | Purpose |
|------|---------|
| `EventsApiClient.java` | `fetchEvents()` and `signup()` - builds requests, attaches Bearer auth header, parses JSON via Gson, routes errors through `ApiCallback`. |
| `AlertsApiClient.java` | Four `sendAlert()` overloads to `POST /alerts` with the same Bearer auth pattern: with/without an image part, each with/without an optional `title` field (accomplishment/pet alerts pass one; loot/death/coffer don't and are unchanged) - all share one request-building/response-handling path. Has its own inline 401/unsuccessful/network handling rather than sharing `EventsApiClient`'s (WRN-005). |
| `ApiCallback.java` | Generic async result interface (`onSuccess`/`onError`) used by all API calls. |
| `ApiErrorType.java` | Enum classifying failures: `UNAUTHORIZED` (401), `NETWORK` (never reached server), `SERVER` (unexpected status/malformed body). |

### Dependencies
- **Depends on:** `src/main/java/com/catastrophic/events/api/dto`
- **Used by:** `src/main/java/com/catastrophic/events`, `src/main/java/com/catastrophic/events/alerts`

## Alerts

**Path:** `src/main/java/com/catastrophic/events/alerts`
**Responsibility:** Game-event listeners that detect loot/death/clan-coffer/accomplishment/pet moments client-side and hand off to `AlertsApiClient` for delivery to Discord via catabot. Most are `@Subscribe` on RuneLite's `EventBus`; `QuestMilestoneListener` is the one exception (see its entry below). Loot, death, pet drops, and 1750/2000/2200 total-level milestones capture a screenshot first; coffer, quest, other skill/XP milestones, and one-time-reward alerts post text only.
**Entry points:** `LootAlertListener.java`, `DeathAlertListener.java`, `CofferAlertListener.java`, `SkillMilestoneListener.java`, `QuestMilestoneListener.java`, `PetDropListener.java`, `OneTimeRewardListener.java`

### Key files
| File | Purpose |
|------|---------|
| `AlertKind.java` | `LOOT`/`DEATH`/`COFFER`/`ACCOMPLISHMENT`/`PET` enum; `wireValue()` matches the bot's `kind` field. |
| `ScreenshotCapture.java` | Wraps `DrawManager.requestNextFrameListener` to capture the current client frame as PNG bytes via an async callback. |
| `LootAlertListener.java` | `@Subscribe` on `NpcLootReceived`, `PlayerLootReceived`, and RuneLite's own `LootReceived` (filtered to `LootRecordType.EVENT`/`PICKPOCKET` - catches chest/reward-interface content like Doom of Mokhaiotl that the first two never fire for; `NPC`/`PLAYER`-typed `LootReceived` is skipped to avoid duplicating the other two sources). Per item, independently runs two checks: non-stackable + worth >= 1.5m gp (`ItemManager.getItemPrice`) posts `AlertKind.LOOT`, gated on `lootSharingEnabled` (default off); item ID in a fixed 7-entry mega-rare allowlist (Twisted bow, Scythe of vitur, Tumeken's shadow, Ancient blood ornament kit, Mokhaiotl cloth, Eye of Ayak (uncharged), Avernic treads) regardless of value posts `AlertKind.ACCOMPLISHMENT` with a title, gated on `accomplishmentSharingEnabled` (default off) - an item can trigger both. Absorbed the former `AccomplishmentLootListener.java` (deleted) - see `architecture.json` key_decisions. |
| `DeathAlertListener.java` | `@Subscribe` on `ActorDeath`, local player only; gated on `config.deathScreenshotsEnabled()` (default off); uses `config.deathMessage()` if set, else "Died." |
| `CofferAlertListener.java` | `@Subscribe` on `ChatMessage` (`ChatMessageType.CLAN_MESSAGE` only - the system-broadcast type, not player-typed `CLAN_CHAT`); regex-matches coffer deposit/withdraw text; posts via `AlertsApiClient`'s text-only `sendAlert` overload (no `ScreenshotCapture` dependency); always on, no config gate. |
| `SkillMilestoneListener.java` | `@Subscribe` on `StatChanged`; tracks per-skill previous level/XP plus total level/XP (via `Client.getTotalLevel()`/`getOverallExperience()`, not a `Skill.OVERALL` `StatChanged` event) in-memory, never alerting on a skill's first observation this session (avoids false-firing on a veteran account's pre-existing 99s). Detects 99s, every 25m skill-XP milestone past 99, and every 50m total-XP milestone (all text-only). Total level milestones fire only for exactly 1750/2000/2200, each with a `ScreenshotCapture` screenshot - all other totals, including the previous max-cape (2277) special case, no longer alert. Gated on `accomplishmentSharingEnabled`. |
| `QuestMilestoneListener.java` | No EventBus `@Subscribe` - there is no `QuestCompleted` event in this RuneLite version (confirmed by extracting the pinned `client`/`runelite-api` jars). Exposes `checkQuests()`, called from `CatastrophicEventsPlugin.pollEvents()`'s 45s loop, which reads `Quest.getState(Client)` for a fixed allowlist of 7 GM/special quests and tracks previous state per quest the same veteran-safe way as `SkillMilestoneListener`. Gated on `accomplishmentSharingEnabled`. |
| `PetDropListener.java` | `@Subscribe` on `ChatMessage`, filtered to `ChatMessageType.GAMEMESSAGE` (closes a chat-spoofing gap - previously unfiltered, confirmed exploitable via a real Discord incident); regex matches the three known pet-obtained message variants (first-time boss/minigame pet, duplicate pet roll, skilling pet). Captures a screenshot via `ScreenshotCapture` and attaches it to the alert. Gated on `petDropSharingEnabled`. |
| `OneTimeRewardListener.java` | `@Subscribe` on `ChatMessage`, filtered to `ChatMessageType.GAMEMESSAGE` (same chat-spoofing fix as `PetDropListener`); keyword-pair regex per reward (fire cape, infernal cape, Dizana's quiver) plus a completion-verb stem. Each reward gated by its own one-time `ConfigManager` flag (same pattern as `CatastrophicEventsPlugin`'s `DEATH_MESSAGE_NAME_TOKEN_MIGRATED_KEY`) so it can never re-fire. Named to avoid ambiguity with the real Achievement Diary cape, which this feature excludes. Exact wording still unverified against a live client, see WRN-007. Gated on `accomplishmentSharingEnabled`. |
